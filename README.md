# FamilyChat

FamilyChat — семейный мессенджер, который вы разворачиваете на своём сервере. Он подходит для общения с близкими и небольшими закрытыми сообществами: вы управляете участниками, хранением переписки и файлов, обновлениями и резервными копиями.

Пользователи общаются в приложениях **iOS, Android и macOS**. Для входа нужны логин и пароль; телефон и электронная почта участника не требуются. Один аккаунт можно использовать на нескольких устройствах. Веб-панель `/admin/` предназначена для администрирования сервера.

## Возможности

- Личные и групповые чаты, история сообщений и отметки доставки и прочтения.
- Реакции emoji на свои и чужие сообщения: одна реакция пользователя на сообщение, с возможностью заменить или убрать её.
- Фото и видео с превью, обмен другими файлами; доступ к вложениям проверяется по участию в чате.
- Аудио- и видеозвонки один на один через WebRTC, с TURN для соединения между разными сетями.
- Сторис с фото, видео и подписью, доступные в течение 24 часов.
- Профили с именем и аватаром, поиск пользователей, приглашения и управление участниками.
- Уведомления через APNs для iOS; FCM для Android — при отдельной ручной настройке Compose.
- Шифрование текста, вложений и превью перед отправкой; поиск по расшифрованной истории на устройстве.
- Необязательный отдельный сервер ключей с независимым подключением каждого устройства.

## Установка на VPS

Основной путь установки — готовый релиз. Установщик скачивает образы и проверенный по SHA-256 комплект; собирать приложение на VPS, устанавливать Go, Node.js или Git не нужно.

### 1. Подготовьте сервер и адрес

Понадобятся:

- Ubuntu или Debian с systemd, архитектура amd64 или arm64, доступ по SSH и права `sudo` либо root.
- Публичный IPv4 и домен, например `chat.example.com`. Его A-запись должна указывать на этот VPS. Для стандартного установщика отключите CDN-проксирование и удалите AAAA-запись: этот путь рассчитан на IPv4.
- Свободные порты из таблицы ниже и разрешения в firewall VPS и панели хостинга.
- Доступ сервера к GitHub, GHCR и службам выпуска сертификатов по HTTPS.
- Место для образов, базы, файлов и резервных копий. Практический ориентир для старта — диск 25–30 ГБ; перед установкой и обновлением оставляйте хотя бы 3 ГБ свободного места. Объём вложений и миграции могут потребовать больше.

| Порт | Для чего нужен |
| --- | --- |
| TCP 80 | Выпуск и продление HTTPS-сертификата, перенаправление на HTTPS |
| TCP 443 | Подключение приложений, API и админ-панель |
| TCP и UDP 3478 | TURN для звонков |
| UDP 55000–55039 | Передача медиаданных через TURN |

PostgreSQL и S3 в стандартной установке не публикуются наружу. Доступ по SSH сохраняйте на порту, выбранном при настройке VPS.

Если 80 или 443 уже заняты другим приложением, сначала выберите схему совместного размещения. Установщик ожидает свободные порты и не останавливает чужие службы. Варианты с существующим reverse proxy, своим сертификатом, публичным IP без домена и нестандартными портами описаны в [подробной инструкции HTTPS](deploy/README.md#https-развёртывание-сервера).

Установка на домашнем мини-ПК также требует доступного извне адреса и настройки переадресации портов; обычный локальный адрес за NAT для стандартной установки не подходит.

### 2. Запустите установщик

Подключитесь к VPS по SSH в обычном интерактивном терминале. Сначала установите базовые зависимости:

```sh
sudo apt-get update
sudo apt-get install -y curl ca-certificates python3 openssl
```

Затем выполните:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/balamutik/familychat-server/releases/latest/download/install.sh | sudo bash
```

Мастер спросит домен и email для HTTPS-сертификата, предложит установить недостающие Docker Engine и Compose. Дождитесь завершения всей команды и сообщения с адресом админки и учётными данными администратора. Ввод ответов работает и при запуске через `curl | sudo bash`.

В результате будут созданы:

- установка в `/opt/familychat`, закрытые настройки и секреты;
- контейнеры API, worker, PostgreSQL, SeaweedFS, TURN и nginx;
- HTTPS-сертификат и ежедневный таймер его продления;
- первый администратор с логином `admin` и случайным паролем.

Для готового релиза вход в GitHub или Docker registry не требуется. При уже установленном Docker нужны рабочие `sudo docker info` и `sudo docker compose version`; минимальная версия Compose — **2.24.4**. Старая команда `docker-compose` не заменяет Compose plugin. Если с зависимостями возникла ошибка, смотрите [подготовку Docker и Compose](deploy/README.md#подготовка-зависимостей).

### 3. Проверьте установку

Подставьте свой домен:

```sh
sudo familychat status
curl --fail https://chat.example.com/health/ready
```

Откройте `https://chat.example.com/admin/` и войдите с данными, показанными установщиком. Первоначальный пароль также хранится в закрытом файле `/opt/familychat/secrets/admin-password.txt`; после смены пароля этот файл не отражает новое значение.

## Первый вход и участники

1. Установите актуальное приложение FamilyChat для своей платформы. Серверный установщик не устанавливает приложения на телефоны и компьютеры.
2. В приложении добавьте адрес `https://chat.example.com` — без `/admin/` и `/api/v1/` — и войдите по логину и паролю.
3. В админке создайте аккаунты близких либо включите самостоятельную регистрацию в разделе «Доступ». По умолчанию она выключена.
4. В разделе «Приглашения» создайте ссылку на сервер и отправьте её участникам. Ссылка помогает добавить сервер в приложение; аккаунт по ней не создаётся, а выключенная регистрация не обходится.
5. Найдите собеседника по логину, создайте личный или групповой чат. Проверьте сообщение, вложение и звонок между двумя устройствами.

Участники могут пользоваться одним аккаунтом с нескольких устройств. Доступ к истории и вложениям зависит от членства в чате; блокировка аккаунта отзывает его сессии.

В разделе «Хранение» задаются срок хранения вложений и предел размера новых загрузок. Значение срока `0` означает бессрочное хранение. Сокращение срока действует и на ранее загруженные вложения: они становятся недоступны, затем worker удаляет их; сообщения остаются в истории. Увеличение срока не возвращает уже удалённые файлы. По умолчанию серверный предел — 250 МиБ на файл и 10 ГиБ квоты на пользователя; верхние пределы задаются в настройках сервера.

Сторис доступны 24 часа и могут быть удалены автором раньше. В приложениях действуют ограничения: файл до 50 МБ, видео до 60 секунд и подпись до 500 символов. Размер загрузки также ограничивается настройками сервера и квотой пользователя.

## Отдельный сервер ключей

Это необязательный сервис для хранения и выдачи ключей переписки на другом хосте. Обычная установка работает с ключами в Docker secrets на VPS чата. При подключении отдельного сервера основной API использует публичный ключ и секрет регистрации устройств, а ключи для расшифровки приложения получают напрямую от сервера ключей.

Нужны **FamilyChat v2.4.0 или новее**, **keyserver v1.1.0 или новее** и клиенты с поддержкой `device-grant-v1`. Сначала обновите приложения, затем серверы. Старый внешний протокол выдачи по JWT больше не поддерживается.

### Установите и свяжите оба сервера

Для подключения двумя командами **оба сервера уже должны быть установлены**. `prepare-chat` подготавливает существующий чат, а не разворачивает его с нуля.

1. Установите основной чат по инструкции выше.
2. На втором VPS установите сервер ключей:

   ```sh
   curl --proto '=https' --tlsv1.2 -fsSL https://github.com/balamutik/familychat-keyserver/releases/latest/download/install.sh | sudo bash
   ```

   Мастер предложит Certbot или acme.sh. Служба использует HTTPS на отдельном порту **8443**; откройте его для основного сервера и пользовательских устройств. Порт можно изменить. Для проверки сертификата HTTP-01 нужен также доступный извне TCP 80; варианты webroot и DNS-01 описаны в [README сервера ключей](https://github.com/balamutik/familychat-keyserver#readme).
3. Подготовьте подключение на VPS чата. Ниже пример для SSH-пользователя `root`; если вы подключаетесь другим пользователем с `sudo`, замените его имя в обеих командах:

   ```sh
   curl --proto '=https' --tlsv1.2 -fsSL https://github.com/balamutik/familychat-keyserver/releases/latest/download/install.sh | sudo bash -s -- prepare-chat --ssh-user root
   ```

   Дождитесь сообщения о завершении подготовки и готовой второй команды. Явный `--ssh-user` позволяет обойти запрос имени пользователя.
4. Выполните вторую команду **на VPS ключей**, заменив `chat.example.com` адресом VPS чата, доступным по SSH:

   ```sh
   curl --proto '=https' --tlsv1.2 -fsSL https://github.com/balamutik/familychat-keyserver/releases/latest/download/install.sh | sudo bash -s -- connect-chat --chat root@chat.example.com
   ```

   Подтвердите SSH-ключ узла и введите пароль SSH или `sudo`, если их запросит система. Можно использовать готовую команду из предыдущего шага.

Процедура переносит **исходную пару ключей чата** на ещё не используемый сервер ключей, создаёт резервные копии и сохраняет историю. Новую пару для существующей переписки создавать нельзя. При обрыве соединения повторите вторую команду: журнал позволяет продолжить подключение.

После успешного подключения проверьте старые сообщения и вложения на клиентах. Исходные файлы ключей на VPS чата и прежние резервные копии автоматически не удаляются. Если цель — убрать приватный ключ с основного хоста, перенесите эти копии за его пределы после проверки истории и сохранения резервной копии.

Для новой установки, при которой приватный ключ вообще не создаётся на VPS чата, сначала установите сервер ключей, перенесите только закрытый файл `export/main-server.json` и передайте `--key-service-config /root/main-server.json` установщику чата. Этот вариант и ручной перенос описаны в [инструкции подключения](deploy/README.md#отдельный-сервер-ключей).

### Как устройство получает ключи

После входа новое устройство создаёт свою пару P-256. Основной сервер регистрирует для него одноразовый допуск на 120 секунд. Клиент обращается к серверу ключей по HTTPS, подписывает запрос и сохраняет полученную пару локально: Keychain на iOS/macOS, защищённое хранилище с Android Keystore на Android.

Устройства одного аккаунта получают независимые допуски. Использованный допуск отклоняется и после перезапуска сервера ключей. При потерянном ответе клиент запрашивает новый. Обычный запуск использует сохранённый ключ; повторная выдача нужна после очистки данных, переустановки или смены ключа. При недоступности службы новые устройства без локальной пары не смогут получить ключи.

## Уведомления и звонки

Сообщения и звонки в открытом приложении работают через API и WebSocket. Для уведомлений и входящих вызовов в фоне настройте push для нужных платформ. HTTPS-сертификат, APNs-ключ и ключи шифрования переписки — разные вещи.

### iOS: APNs

Нужны Apple Developer, включённая возможность Push Notifications для App ID и ключ APNs `.p8`. Скопируйте ключ на VPS по защищённому каналу и выполните:

```sh
sudo familychat configure-push --push-mode direct
```

Мастер запросит путь к `.p8`, Key ID, Team ID, Bundle ID **вашей сборки** и среду: `development` для development-профиля Xcode либо `production` для TestFlight/App Store. Среда должна совпадать с подписью приложения; одна установка использует одну среду APNs. API и worker будут перезапущены.

В приложении разрешите уведомления и микрофон, для видео — камеру. Проверьте сообщение и звонок со второго устройства в открытом приложении, в фоне и на заблокированном экране. Сам факт сохранения настроек не подтверждает доставку через Apple.

### Отдельный push-шлюз: iOS и Android

Ключи Apple/Google можно хранить на отдельном [push-шлюзе](deploy/push-gateway/README.md). При первой установке укажите его HTTPS-адрес и путь к индивидуальному токену, либо настройте позже:

```bash
sudo familychat configure-push --push-gateway-url https://push.example.com:9443 --push-gateway-token-file /root/family-one.token
```

Те же параметры поддерживает `install.sh`. Без аргументов `configure-push` предлагает шлюз, прямой APNs или отключение push. Нужен релиз с поддержкой шлюза; переключение пересоздаёт API и worker. Шлюз заменяет имена общими подписями FamilyChat и не получает текст переписки. Старые файлы provider-ключей сохраняются, но больше не монтируются в worker.

### Android: FCM

Нужны Firebase-проект, Cloud Messaging API v1, сервисный аккаунт для серверной отправки и `google-services.json` для сборки Android. Файл сервисного аккаунта остаётся только на сервере и не включается в APK.

FCM настраивается через `FCM_CREDENTIALS_FILE`, `FCM_PROJECT_ID`, `FCM_APPLICATION_ID` и отдельный [Compose override](compose.fcm.yaml). **В текущий готовый релиз этот override не входит, и штатный менеджер релизов его не обслуживает.** Для Android push используйте установку из исходников или собственную Compose-конфигурацию по [инструкции FCM](docs/android/FCM.md).

В режиме `direct` команда `familychat configure-push` настраивает только APNs; в режиме `gateway` обе платформы обслуживает отдельный шлюз. Ручное добавление FCM к релизной установке само по себе недостаточно: последующий `familychat update` или `configure-push` может пересоздать контейнеры без этого override. В собственной конфигурации подключайте его при каждом пересоздании API и worker. Android-уведомления требуют Google Play services; запрет уведомлений, force-stop и ограничения производителя могут мешать доставке.

### Если звонки не соединяются

TURN должен быть доступен по TCP/UDP 3478 и UDP 55000–55039. В исходной конфигурации `TURN_URL` и `TURN_EXTERNAL_IP` должны указывать на публичный адрес сервера; `127.0.0.1` подходит только для локальной проверки. При NAT требуется корректная переадресация портов. Проверяйте звонок между разными сетями, например Wi-Fi и мобильной связью.

## Обновление и обслуживание

Команды ниже относятся к установке готового релиза:

| Команда | Действие |
| --- | --- |
| `sudo familychat status` | Версия и состояние контейнеров |
| `sudo familychat logs` | Последние записи и поток журналов; `Ctrl+C` прекращает просмотр |
| `sudo familychat update` | Установка последнего стабильного релиза |
| `sudo familychat renew` | Ручная проверка и продление HTTPS-сертификата |
| `sudo familychat configure-push` | Push-шлюз, прямой APNs или отключение push |

Перед обновлением подготовьте согласованную резервную копию и проверьте свободное место. Обновляйте совместимые версии клиентов и сервера; для перехода на внешнюю выдачу ключей по устройствам сначала обновляются клиенты. Установщик сохраняет настройки и ключи, скачивает новый образ и применяет миграции БД. На время обновления соединения могут прерываться; миграция большого объёма данных может занять время.

Для выбора конкретного опубликованного релиза есть `familychat update --version vX.Y.Z`. Выбор старой версии не откатывает миграции; несовместимый откат протокола шифрования или выдачи ключей блокируется. Если обновление прервалось, устраните причину и повторите `sudo familychat update` **без указания другой версии**.

Сертификат основного сервера продлевается ежедневным `familychat-renew.timer`:

```sh
sudo systemctl status familychat-renew.timer --no-pager
```

Сервер ключей обслуживается отдельно. Для его обновления:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/balamutik/familychat-keyserver/releases/latest/download/install.sh | sudo bash -s -- update
```

Повторный запуск установщика чата сохраняет завершённую установку и пароль, но не заменяет команду `familychat update`. Существующая ручная установка из Git автоматически в релизную не импортируется.

## Резервные копии и восстановление

Образы Docker и каталог установки сами по себе не являются полной резервной копией. Сохраняйте вместе:

| Данные | Где находятся в стандартной установке |
| --- | --- |
| Сообщения, пользователи, сессии, настройки | PostgreSQL, том `familychat_postgres_data` |
| Вложения, превью, сторис и аватары | SeaweedFS/S3, том `familychat_s3_data` |
| Секреты, состояние установщика, сертификаты | Каталог `/opt/familychat`, включая `secrets/`, `.env`, `.https/` и `installation.json` |
| Исходная пара шифрования | `secrets/content-public-key.txt` и `secrets/content-private-key.txt` либо состояние отдельного сервера ключей |

Для PostgreSQL используйте `pg_dump` или согласованный снимок, для S3 — штатное резервирование хранилища. Снимки должны соответствовать друг другу; на время согласованного копирования остановите запись через API и worker. Для старой установки v2.0.0 сохраните также прежний том `encryption_keys`.

При отдельном сервере ключей используйте его команду резервирования:

```sh
sudo /opt/familychat-keyserver/app/scripts/backup.sh --output /root/keyserver-backup.tar.gz
```

Она выполняется на VPS ключей и включает приватную пару, секрет регистрации, журнал допусков и настройки службы. Архив не зашифрован дополнительно; храните копии с ограниченным доступом вне исходного сервера.

При восстановлении остановите API и worker, восстановите согласованные БД, S3, настройки и **ту же пару ключей**, затем проверьте готовность сервера, вход, старые сообщения и вложения. Без исходного приватного ключа зашифрованную историю восстановить нельзя.

`docker compose down -v` и `docker volume prune` могут удалить данные; это не команды обновления или восстановления. Подробности хранения и восстановления — в [инструкции развёртывания](deploy/README.md).

## Как защищаются данные

Содержимое использует формат `fc1`: клиенты шифруют тексты, файлы, подписи сторис и превью перед отправкой. Сервер хранит шифротекст; поиск выполняется на устройстве. Ключи локально разделены по серверу, аккаунту и версии ключа; при выходе или удалении сохранённого сервера соответствующие локальные ключи очищаются.

Используется **общая пара ключей установки, а не сквозное шифрование между отдельными собеседниками**. В обычном режиме приватный ключ хранится в файлах Docker secrets на основном VPS. В Compose это файлы хоста, а не зашифрованное хранилище Docker Swarm. В режиме отдельной службы приватный ключ не монтируется в основной API и не скачивается им.

Основной сервер остаётся доверенной стороной регистрации: его полный захват позволяет разрешить подключение постороннего устройства. Отдельный сервер ключей не устраняет эту границу доверия. Отзыв доступа не уничтожает уже полученные пользователем копии ключей и данных.

Имена пользователей и чатов, состав участников, имена/MIME/размеры файлов, даты, реакции и квитанции остаются метаданными. Аватары публичны по URL. Оригиналы вложений и их превью доступны через API после проверки сессии и членства в чате; приватный S3 не выдаёт клиентам публичные ссылки. Push не содержит текста сообщений или ключей переписки. Содержание звонков передаётся по WebRTC, а не хранится в истории чата.

## Если что-то не работает

Начните с безопасной диагностики:

```sh
sudo familychat status
sudo docker ps -a --filter label=com.docker.compose.project=familychat
df -h /
sudo ss -ltnup
```

Для журналов используйте `sudo familychat logs`. Перед передачей вывода проверьте, что в нём нет секретов и токенов.

| Симптом | Что проверить |
| --- | --- |
| «Порт 443 занят» | Какой сервис слушает порт; выберите схему размещения до повторной установки |
| `docker` или `docker compose` не работает | Состояние Docker, наличие Compose plugin и его версию; [инструкция](deploy/README.md#подготовка-зависимостей) |
| Не открывается HTTPS | A-запись, отсутствие лишней AAAA, firewall, порты 80/443 и состояние сертификата |
| Сообщения приходят только после открытия приложения | Настройки APNs/FCM, разрешения уведомлений и соответствие конфигурации сборке |
| Звонок принимается, но связи нет | Публичный адрес TURN, TCP/UDP 3478 и UDP 55000–55039 |
| `encryption_unavailable` или ошибка получения ключей | Доступность HTTPS сервера ключей с VPS и устройства, его порт, время на серверах и совместимость клиентов |
| `attention` или «Другая команда FamilyChat уже выполняется» | Дождитесь завершения предыдущей команды; при `prepare-chat` проверьте запрос SSH-пользователя в первом терминале. Для следующего запуска укажите `--ssh-user`. Не удаляйте файл блокировки для обхода проверки |
| `No space left on device` или ошибка PostgreSQL после заполнения диска | Свободное место и состояние БД; [порядок восстановления](deploy/README.md#восстановление-после-ошибок) |

Во время первой миграции старой незашифрованной истории API может быть недоступен: миграция шифрует данные и возобновляется после прерывания. Не удаляйте тома, WAL PostgreSQL или таблицу миграций ради повторного запуска. Старые резервные копии могут сохранять прежний открытый текст — учитывайте это при их хранении.

## Для разработчиков

Сервер написан на Go, админ-панель — на React. Compose объединяет API, worker, PostgreSQL, приватное S3-хранилище SeaweedFS, coturn и HTTPS-прокси nginx. Приложения разрабатываются в отдельных проектах iOS, Android и macOS; этот репозиторий содержит сервер и админку.

### Локальный запуск из исходников

Из корня этого репозитория при установленном Docker Compose:

```sh
cp .env.example .env
# Замените POSTGRES_PASSWORD, S3_ACCESS_KEY, S3_SECRET_KEY и TURN_SECRET в .env.
mkdir -p secrets
printf '%s\n' 'замените-на-длинный-случайный-пароль' > secrets/admin-password.txt
chmod 700 secrets
chmod 600 .env
chmod 644 secrets/admin-password.txt
docker compose run --rm --build key-setup
docker compose up -d --build
docker compose run --rm api bootstrap-admin
```

Админка будет доступна на `http://localhost:8080/admin/`. Файл первоначального пароля должен читаться API внутри контейнера, поэтому при закрытом каталоге `secrets` используется режим `0644` для самого файла. `.env` и `secrets/` исключены из Git. Локальный HTTP подходит для проверки на loopback; для подключения устройств используйте HTTPS по [инструкции](deploy/README.md#https-развёртывание-сервера).

`key-setup` создаёт исходную пару X25519 в Docker secrets и при повторном запуске сохраняет её. При обновлении ручной установки сначала остановите старые API и worker, подготовьте ключи и запустите обновлённые контейнеры. Для режима внешней службы используется дополнительный `compose.keyserver.yaml`; подробности — в инструкции развёртывания.

### Формат шифрования fc1

- [HPKE RFC 9180](https://www.rfc-editor.org/rfc/rfc9180.html), base mode,
  DHKEM(X25519, HKDF-SHA256), HKDF-SHA256, AES-256-GCM. Используются стандартный
  Go `crypto/hpke` и Apple CryptoKit, с взаимными тестовыми векторами.
- Заголовок: ASCII `FCENC001` (8 байт), SHA-256 публичного ключа (32), HPKE
  encapsulated key (32), размер открытых данных uint64 big-endian (8).
- Далее блоки открытого текста до 1 МиБ с 16-байтным тегом каждый. Для пустых
  данных есть один блок с тегом. Каждый блок аутентифицирует весь заголовок;
  порядок задаётся счётчиком HPKE. Новый контекст создаётся для каждого объекта.
- HPKE info: `FamilyChat/v1/` + контекст. Для текста контекст
  `message:<chat_uuid>:<sender_uuid>:<client_message_uuid>`, для файла
  `file:<chat_uuid>`, для превью `preview:<chat_uuid>`; UUID в нижнем регистре.
- `text` в JSON — base64 конверта и `encrypted: true`; бинарные тела файлов
  передаются без base64. Размер тела — `80 + plaintext_size + 16 * max(1, ceil(plaintext_size / 1048576))`.
  У загрузки обязательны `X-Plaintext-Size`, `X-Content-Encryption: fc1` и обычные
  заголовки имени/MIME. Затем клиент может выполнить
  `PUT /files/{id}/preview` с зашифрованным превью до 1 МиБ открытых данных.
  До успешного PUT состояние превью — `unsupported`, после — `ready`. Ошибка
  загрузки превью не отменяет успешную загрузку оригинала и отправку вложения.
- Range относится к смещениям **шифротекста**. Неполный, изменённый или избыточный
  конверт не сохраняется как готовый открытый файл. Повтор сообщения с тем же
  `client_message_id` и теми же вложениями возвращает первую запись, даже если
  рандомизированное шифрование при повторе дало другие байты.
